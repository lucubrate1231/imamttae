# 조사: 장면마다 다른 카카오톡 미리보기 (D15)

> 조사: Claude Code(개발 리드) · 2026-10-04 · 요청: 기획(D15, "비공개 베타 전에 알려 줘")
> 결론만 먼저: **어느 방법이든 부담은 작습니다.** 결정할 것은 "어떤 모양의 공유를 원하느냐"입니다. 알파는 정한 대로 앱 공통 미리보기로 갑니다.

## 왜 지금은 장면마다 다르게 안 뜨나
카카오톡은 링크를 받으면 그 주소의 HTML을 읽어 미리보기(제목·설명·그림, `og:` 정보)를 만듭니다.
그런데 장면 주소는 `…/#/scene/s-005-biryong`처럼 `#` 뒤에 장면이 붙습니다. `#` 뒤는 서버로 가지 않아서, 카카오톡은 **어느 장면이든 첫 화면 HTML 하나**만 읽습니다. 그래서 모두 같은 미리보기가 뜹니다.

## 방법 A — 장면별 공유용 작은 페이지
빌드할 때 장면마다 `…/s/<장면 id>/` 작은 HTML을 만듭니다. 그 안에 그 장면의 제목·한 줄 소개·사진을 미리보기 정보로 넣고, 사람이 열면 곧바로 앱의 그 장면(`#/scene/…`)으로 넘깁니다. 공유 버튼은 이 주소를 보냅니다.

**시제품으로 잰 부담(10/4, 장면 85곳)**
| 항목 | 결과 |
|---|---|
| 만드는 시간 | 0.08초(빌드 전체에 영향 없음) |
| 페이지 크기 | 85개 합계 89KB(한 장 약 1KB) |
| 저장소 크기 | 0 — 빌드할 때 만들고 저장소에는 넣지 않음. 배포 가지(gh-pages)에는 장면이 바뀔 때만 조금씩 늘어남 |
| 사진 | 복사하지 않음. 다음 썸네일 서버가 2:1(800×400)로 잘라 주는 주소를 그대로 씀. 미리보기 그림 한 장 약 100~200KB(PNG 원본은 700KB까지), 카카오가 한 번 읽어 감 |
| 앱 무게 | 그대로(앱 JS에 더하는 것 없음) |

**좋은 점:** 카카오톡뿐 아니라 문자·밴드·페이스북 등 어디에 붙여도 장면별 미리보기가 뜹니다. 휴대폰 공유 창(지금 쓰는 방식)을 그대로 씁니다.
**신경 쓸 점**
- 열 때 작은 페이지를 한 번 거쳐 앱으로 넘어갑니다(눈에 거의 안 띔).
- 썸네일은 사진 가운데를 자릅니다. 장면마다 정한 초점(`focus`)은 반영되지 않습니다. 필요하면 미리보기용 초점을 따로 둘 수 있습니다.
- 카카오는 한 번 읽은 미리보기를 한동안 기억합니다. 사진을 바꾸면 카카오 개발자 도구에서 기억을 지워야 바로 바뀝니다.
- 공유 주소가 `…/s/…/` 모양으로 바뀝니다(받은 사람이 열면 같은 장면).

## 방법 B — 카카오톡 공유 기능 직접 쓰기
이미 쓰는 카카오 JavaScript 키로 '카카오톡 공유'(카카오 SDK)를 부르면, 페이지 없이도 장면마다 제목·사진·버튼을 정해서 보낼 수 있습니다.

**좋은 점:** 미리보기 모양을 더 예쁘게 정할 수 있습니다(큰 사진 + '장면 보기' 버튼). 작은 페이지가 필요 없습니다.
**신경 쓸 점**
- **카카오톡으로만** 보낼 수 있습니다. 문자·밴드 등은 따로 휴대폰 공유 창을 둬야 합니다(버튼이 둘이 됨).
- 공유 버튼을 누를 때 카카오 SDK를 한 번 더 불러옵니다(앱 첫 화면 무게에는 영향 없음).
- 카카오 개발자 설정에서 '카카오톡 공유' 사용과 등록 도메인을 확인해야 합니다(외부 서비스 설정 → 사용자 결정).

## 개발 리드 의견
- **방법 A를 추천합니다.** 지금 공유 버튼(휴대폰 공유 창)을 그대로 두고, 대상(50~60대)이 많이 쓰는 카카오톡과 문자 모두에서 장면 사진이 뜹니다. 부담은 위 표처럼 작고, 카카오 설정을 바꿀 필요가 없습니다.
- 시점: 비공개 베타 전 PR 하나(빌드 단계 + 공유 버튼 주소 + 테스트). 알파는 앱 공통 미리보기 그대로.
- 정할 것(기획): ① A/B 중 어느 것 ② 미리보기 문구(제목 '장면 이름 · 이맘때 풍경', 설명은 한 줄 소개가 기본안) ③ 준비 중 장면은 앱 공통 미리보기로 둘지.
