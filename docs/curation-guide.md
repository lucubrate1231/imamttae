# 장면 초안 만들기 안내 (큐레이션 가이드)

브런치 발행 글에서 앱의 **자연 풍경** 초안을 만드는 방법입니다. 초안은 작가 확인을 거쳐 앱에 들어갑니다.
Claude(또는 도우미 에이전트)가 이 문서대로 작업하고, `pipeline/scenes/check-cli.ts` 검사를 통과해야 합니다.

## 준비
- 원문: `.cache/brunch/NN.json`(`npx tsx pipeline/sync.ts`로 받음). 문단은 `items[].t === 'p'`의 `text`입니다.
- 사진 모음(작업 공간): `/home/claude/curation/sheets/NN.jpg`. 각 사진의 라벨은 아래 순서입니다.
  - 순번
  - L(가로)/P(세로)와 원본 폭
  - s(선명도, 높을수록 선명. 300 아래는 흐림 의심)
  - t(수평 기울기 추정, 도)
- 점수 원본은 `/home/claude/curation/scores.json`에 있습니다. 키는 `"글번호_순번"`입니다.
- 사진을 자세히 보려면 `/home/claude/curation/thumbs/NN_ii.jpg`를 엽니다.
- 사진 순번은 `content/brunch/index.json`의 그 글 `photos` 배열 순서와 같습니다. 주소(src)는 거기서 가져옵니다.
- **좌표는 콘텐츠 세션이 골라 넣어요(D47, 10/6).** 사용자는 콘텐츠 세션이 '좌표 확인 필요'로 표시한 곳만 봐요. 새 장면은 처음부터 카카오 좌표 없이 만들어요.
  - **쓰지 않는 것:** 카카오 장소 검색·카카오맵(웹·앱)에서 좌표·장소 이름 가져오기, 카카오 지도를 보며 찍기(로컬 API 결과 저장 금지 — 사람이 고쳤어도 해당, `docs/kakao-local-data.md`). 네이버·구글 지도도 저장을 막는 약관이라 쓰지 않아요.
  - **쓰는 것(이 순서로):**
    1. `tools/places/candidates.json` — 한국관광공사 관광정보(장면 위치 후보)와 전국주차장정보표준데이터(주차장 후보). 새 장면이라 후보가 없으면 Claude Code에 `npx tsx pipeline/places/candidates.ts`(키가 사용자 컴퓨터에 있음)로 다시 만들어 달라고 부탁해요.
    2. 맞는 후보가 없으면 오픈스트리트맵(지명 검색·지도·`api.openstreetmap.org` 원자료)에서 확인한 좌표. `ref`에 `osm:way/번호`처럼 남겨요. 화면에 출처 '© OpenStreetMap contributors'를 표시해요.
  - **고르는 기준**
    - `spot`(장면 위치): 그 사진을 찍은 풍경 지점(전망대·폭포·연못·능선 등). 100m쯤 어긋나도 괜찮아요.
    - `dest`(가는 곳): 실제로 차를 세우고 걸어 들어가는 곳. **공식 주차장 > 탐방로 입구 > 정문** 순, 장면 위치에서 15km 안. 작가 글에 주차·들머리 이야기가 있으면 그것을 먼저 따라요.
    - `dest` 이름: 공공데이터 이름이나 현장 표기로, 50~60대가 길찾기 앱에서 알아볼 이름(예: '백무동 탐방지원센터 주차장').
    - 비공식 갓길·사유지·출입 통제 구역으로 안내하지 않아요(법·개인정보 점검 5번).
    - 자신 없으면 공식 주차장 쪽으로 고르고 `needsCheck: true`와 `why`(짧은 이유)를 붙여 사용자에게 목록(장소 이름·고른 주차장·이유)으로 알려요. 비공개 베타 기준이 '길찾기 오안내 0'이에요.
  - **넣는 법:** 고른 값을 picked 형식(`{ "장면번호": { spot:{lat,lng,source,ref}, dest:{name,lat,lng,kind,source,ref} } }`)으로 `tools/places/picked-content.json`(콘텐츠 세션이 고른 값)에 적어요. 사용자가 고른 값은 `tools/places/picked-seed.json`에 있고 바꾸지 않아요. 그다음
    `npx tsx pipeline/places/apply.ts tools/places/picked-content.json` → `npx tsx pipeline/scenes/check-cli.ts content/scenes/drafts.json` → `npx tsx pipeline/scenes/build.ts` → PR. apply가 `coordSource`(public-data·manual)와 `coordRef`(tour:번호·parking:번호·manual)를 남겨요. 실행 환경이 없으면 picked 파일만 고친 PR을 올리고 Claude Code가 이어서 해요.
  - **사용자가 직접 볼 때(애매한 곳):** 좌표 확인 페이지 https://imamttae.site/next/_review/places/ (휴대폰도 됨) 또는 사용자 컴퓨터 `npm run places`. 다 하면 **[결과 복사]** → 콘텐츠 세션이 `tools/places/picked-seed.json`에 넣어 PR.

## 무엇을 장면으로 고르나
- **자연 풍경만** 고릅니다. 단풍, 꽃, 운해, 물안개, 일출·낙조, 설경·상고대, 억새, 계곡, 폭포, 숲길, 바다 절경 같은 것들입니다.
- 빼는 것:
  - 시장, 음식, 식당, 숙소 안
  - 박물관·전시, 도시 거리
  - 축제의 밤 조명(진주 유등 등)
  - 지인 모임 이야기
- **민간 정원·유료 수목원(D4, 10/3 사용자 결정):**
  - **넣는 것:** 누구나 들어갈 수 있고(입장료가 있어도 됨) **풍경이 주인공**인 곳. `checkAdmission: true`를 붙여 앱이 '입장료·운영 시간 확인' 안내를 보여 주게 합니다. 예: 그레이스정원, 제이드가든, 해남 비원(전남 민간정원 등록), 순천 탐매마을 홍매화(교회 정원 포함).
  - **빼는 것:** 카페·숙박·체험장이 주인인 곳, 누구나 들어갈 수 있는지 불확실한 곳(홍천 자작나무 숲과 같은 기준).
  - 안내는 화면이 고정 한 줄('입장료·운영 시간 확인')로 보여 줍니다. **입장료 금액·운영 시간은 데이터(한 줄 소개·이럴 때 더 좋아요 등)에 적지 않습니다**(값이 자주 바뀜, 10/5 D4 다듬기).
  - 판단이 애매하면 비공개 저장소 메모(`imamttae-notes/scene-notes.json`)에 근거(민간정원 등록 여부, 글에 다른 방문객이 보이는지 등)를 적고 작가 확인을 받습니다.
- **같은 곳을 두 번 다녀온 글(D3, 10/5 사용자):** 사진을 섞지 않고 **더 나은 글 하나로 장면을 만듭니다.** 새 글이 들어오면 장면 확인표의 '같은 곳 비교'에 두 글을 나란히(위아래) 놓고 사용자가 고릅니다. 계절이 다른 장면(예: 상림 꽃무릇·초여름 숲)은 둘 다 둘 수도 있습니다.
- 한 글에서 **1~3곳**을 고릅니다. 같은 장소의 다른 사진은 한 장면에 묶습니다.
- 작가가 직접 걸었거나 본 곳만 고릅니다. 지나가며 언급만 한 곳은 뺍니다.

## 칸마다 쓰는 법 (`shared/schema/content.ts`의 StoryScene)
| 칸 | 쓰는 법 |
|---|---|
| `id` | `s-<글번호 3자리>-<영문 소문자-하이픈>`. 예: `s-020-naejangsan-uhwajeong` |
| `kind` | `"story"` |
| `brunchNo`, `brunchUrl` | 원문 그대로 |
| `name` | 장면 이름, 짧게(14자 안팎). 예: "내장산 우화정", "남설악 주전골" |
| `region` | "도 시군" 짧게. 예: "전북 정읍", "강원 양양", "경북 청송" |
| `types` | 풍경 1~3개: `maehwa` 매화·산수유, `beotkkot` 벚꽃, `jindallae` 진달래·철쭉, `yeoreumkkot` 여름꽃, `kkotmureut` 꽃무릇·가을꽃, `danpung` 단풍·은행, `eoksae` 억새·갈대, `unhae` 운해·물안개, `ilchul` 일출·낙조, `seolgyeong` 설경·상고대, `gyegok` 계곡·폭포, `bada` 바다 절경, `sinrok` 신록·초원(13가지). **사진에 보이는 것**으로 고릅니다. 8월에 찍은 초록 은행나무를 '단풍'으로만 두지 말고, 애매하면 `notes`에 적습니다 |
| `details` | 세부 풍경(D34) 1~5개, 12자 안. 그 장면의 **구체적인 꽃·나무·풍경 이름**(예: 수국, 연꽃, 배롱나무, 유채, 국화, 구절초, 메타세쿼이아, 자작나무, 습지, 폭포, 일출). 큰 갈래 `types`와 따로 적고, 사진에 보이는 것으로. 화면에는 아직 안 보이며 기획이 모아 세어 풍경 찾기에 올릴지 정합니다. 작가 확인 대상 |
| `visited` | 그 장면을 본 날 `YYYY-MM-DD`. 여러 날 여행이면 본문으로 날을 가리고, 모르면 첫날로 합니다 |
| `best` | `{from, to, note, season, tip}`. from·to는 달(1~12), note는 **시기만** 짧게(14자 안, 예: "10월 하순~11월 초", 일 년 내내면 "일 년 내내"). **달 범위는 `N월~N월`**(예: "10월~11월", "5월~6월 신록 숲길"), 같은 달이면 `N월` — `10~11월` 꼴은 검사에서 걸립니다(D68, tip도 같음), tip은 날씨·때 조건(20자 안, 예: "맑은 날, 눈 온 뒤" — 카드에는 안 나오고 장면 상세의 '이럴 때 더 좋아요'에 나옴, 10/3 3차 결정), season은 계절말(8자 안, 예: "늦가을", "초여름", 일 년 내내면 "사계절"). **다녀온 날 ≠ 가장 좋은 때**입니다. 작가가 "아직 푸르렀다"고 쓰면 더 늦게 잡습니다. 아래 기준표를 참고합니다. 비워 둘 수도 있습니다 |
| (제철/기록) | 따로 적지 않고 계산합니다. 다녀온 달이 best 안이면 **제철**(그 철 내내 크게), 아니면 **작가 부부가 다녀온 곳**(지도 범례 '작가 부부 방문', 다녀온 달에만 작게). 일 년 내내(1~12)는 기록입니다. 사진은 다녀온 계절 그대로 보여 주므로, 철 지난 사진을 제철인 척 두지 않습니다(10/3 사용자 결정) |
| `oneLiner` | 처음 보는 사람에게 무엇을 볼 수 있는지 알려 주는 한 줄. **30자 안**. 작가 문장을 베끼지 않습니다(초안) |
| `excerpt` | 작가 글에서 그 풍경을 그린 대목. **한 문단 안의 연속된 원문 그대로**(띄어쓰기·문장부호까지), 30~120자, 완결된 문장. 지인 실명, 음식·잡담은 피합니다 |
| `photos` | 1~4장, **첫 장이 대표**. 아래 사진 기준 참고 |
| `spot` | 풍경 지점 좌표 `{lat, lng}` — 위 '좌표' 방법으로(카카오 검색 금지) |
| `dest` | 길찾기 목적지 = 주차장·입구·탐방로 입구 `{name, lat, lng, kind: parking/trailhead/entrance}`. **spot에서 15km 안** |
| `coordSource` | spot·dest 좌표(와 가는 곳 이름)를 얻은 곳. `"public-data"`(둘 다 공공데이터) 또는 `"manual"`(오픈스트리트맵·사람이 고른 값). `apply.ts`가 적어요. **`"kakao-search"`는 더 쓰지 않아요**(10/6에 0곳). 빠뜨리면 계약 테스트가 알려 줌 |
| `review` | 모두 `"draft"`: `{best, dest, oneLiner, types}` |
| `contestEntry`, `hidden` | `false` |
| `checkAdmission` | 입장료·운영 시간 확인이 필요한 곳(민간 정원·유료 수목원)이면 `true`, 그 밖은 적지 않음(`false`) — 위 '민간 정원' 기준 |
| (메모) | **장면 초안에 두지 않아요.** 작가께 확인할 것(예: "사진 위치가 대승폭포 길인지 확인")은 비공개 저장소 [`imamttae-notes`](https://github.com/lucubrate1231/imamttae-notes)의 `scene-notes.json`(장면 id → 메모)에 적어요(공개 전 점검 6번, 10/5) |

## 콘텐츠 마감 때 점검 (알파 직전, 법무 점검 5번)
장면마다 사진과 장소를 한 번 더 봅니다. 문제가 있으면 사진을 빼거나 장면을 숨깁니다(`hidden: true`).
- **사진:** 얼굴이 알아보이는 사람(작은 뒷모습은 괜찮음), **차량 번호판**(주차장·길 사진), 집 주소·문패, 간판의 전화번호.
- **장소:** 국립공원 **출입 통제 구역·비법정 탐방로**, 사유지·영업장 안쪽, 통제 지점 너머처럼 들어가면 안 되는 곳으로 안내하지 않는지. 가는 곳(주차장)이 공식 주차장인지.
- 발행 글의 법규 문장(차박·취사·통제 구역 진입)은 비공개 저장소의 `legal.json`과 함께 봅니다(D20).

## 사진 기준 (베스트 사진)
1. **선명함:** s 값이 높고 흔들림이 없어야 합니다.
2. **구도:** 풍경이 주인공인 사진을 고릅니다.
3. **사람 얼굴이 보이지 않아야 합니다.** 멀리 작은 뒷모습은 괜찮습니다.
4. **가로 사진, 폭 1000px 이상**을 우선합니다. 대표 사진은 꼭 가로로 고릅니다. 앱에서 3:2로 자르기 때문입니다.
5. **수평이 안 맞아도 좋은 사진이면 고릅니다(사용자 결정).** `rotate`에 바로잡을 각도를 적고(예: `-2`), 비공개 메모에도 적습니다.
6. 중심이 한쪽에 있으면 `focus`를 적습니다(예: `"40% 55%"`, 3:2로 자를 때 중심).
7. 사진 정보 `{src, w, h, cap}`는 index.json 값을 그대로 씁니다.

## 검사와 앱 데이터 만들기
```
npx tsx pipeline/scenes/check-cli.ts <초안파일.json>   # 검사(제철·기록 수도 알려 줌)
npx tsx pipeline/scenes/build.ts                        # 앱 데이터 public/data/scenes.json + 작가 확인용 메모
```

## 작가님께 여쭐 법규 문장 (D20)
- 발행 글에 규칙에 어긋나 보이는 문장(국립·군립공원·사찰 주차장 차박·텐트, 계곡 입수 등)이 남아 있으면 **비공개 저장소 `imamttae-notes`의 `legal.json`**에 적습니다(공개 저장소에는 두지 않음, 10/5). build.ts가 `public/_review/legal.json`으로 옮기고, 작가 확인 페이지(`/_review/check.html`) 맨 위 '글에서 여쭤볼 문장'과 해당 장면의 '문장 확인' 꼬리표로 보입니다.
- 글마다 `status`: 아직 남음 `open`(위치 `where` = '소제목 → 몇 번째 문단', 사유 `why`, 문장 `sentence`) / 고쳐짐 `fixed`(문장 없이).
- 브런치 동기화 뒤 문장이 남았는지 다시 봅니다. **콘텐츠 마감(알파 직전)까지 `open`이 남은 글의 장면은 `hidden: true`로 숨깁니다**(작가님이 고치시면 되살림).
