# 추천 시기를 '공식 예측' 기준으로 — 계산 설계 (D70)

> 상태: **설계안(코드 전)**. 10/10 Claude Code가 썼고, 기획 메시지 BA에 답하는 문서예요.
> 일정: 5단계 정식 출시 준비. 봄꽃 예측이 나오는 2월 전에 돌아가면 돼요.
> 이 문서의 기관 자료 길과 이용 조건은 아는 범위로 정리한 것이라 **'확인 필요'** 칸은 실제로 확인한 뒤 고쳐요.

## 0. 결정(D70, 프프)
- 공식 예측이 있는 풍경(단풍·매화·벚꽃·진달래 등)은 그해 산림청·기상청·국립수목원 예측으로 '지금 좋아요'를 판단해요.
- 예측이 없는 풍경(운해·일출·계곡·바다·신록·설경·억새·꽃무릇 등)은 지금처럼 작가님 시기(`best.from`/`best.to`)를 써요.
- 그해 예측이 나오기 전에는 아래 순서로 정해요.
  1. 작년 실제 관측
  2. 없으면 작년 예측
  3. 그것도 없으면 작가님 시기
- 예측 갱신은 완전 자동이 목표예요.
- 화면 문구는 이번 범위가 아니에요(계산이 끝나고 보여 줄 자리가 정해진 뒤 디자인과).
- 올해(2026) 단풍은 지금 데이터와 대략 맞아서 그대로 둬요.
- 대상 장면(풍경 꼬리표 기준): 단풍 14 · 매화 5 · 벚꽃 3 · 진달래 2. 나머지는 지금 방식 그대로예요.

## 1. 데이터 모양
**`scenes.json`은 그대로 두고, 해마다 '시기 파일'을 따로 둬요.**

### 1-1. 장면 쪽(콘텐츠가 초안에 한 번 적음)
```json
"forecast": { "site": "naejangsan", "kind": "danpung", "zone": "top" }
```
- `site`: 예측 지점(산·도시) 이름표. 목록은 `content/seasons/sites.json`(지점 이름·기관 지점 번호)에 둬요.
- `kind`: `danpung` · `maehwa` · `beotkkot` · `jindallae`
- `zone`: `top`(산 위) · `mid`(중턱) · `low`(산 아래)
- 이 칸이 없는 장면은 지금처럼 작가님 시기를 써요.

### 1-2. 해마다 바뀌는 날짜: `content/seasons/<연도>.json`
```json
{
  "year": 2027,
  "updatedAt": "2027-09-15",
  "sites": {
    "naejangsan": {
      "danpung": { "peak": "2027-10-30", "first": "2027-10-18", "basis": "forecast", "source": "산림청 2027-09-15 단풍 예측 발표" }
    }
  }
}
```
- 단풍: `peak`(절정), 있으면 `first`(첫 단풍)
- 꽃: `bloom`(개화), `full`(만개)
- `basis`: `forecast`(예측) · `observed`(실제 관측)
- 날짜만 옮겨요. 지도 그림은 저장하지 않아요.

### 1-3. 빌드 때 미리 계산 → `public/data/seasons.json`
빌드(`pipeline/scenes/build.ts`)가 장면마다 '좋은 날짜 범위'를 미리 정해 작은 파일로 내보내요.
```json
{ "s-020-naejangsan-uhwajeong": { "from": "2027-10-30", "to": "2027-11-13", "basis": "forecast-2027" } }
```
- 앱은 이 범위만 읽어요. §0의 '예측 → 작년 관측 → 작년 예측 → 작가님 시기' 순서를 앱이 다시 계산하지 않아요.
- 파일이 없거나 장면이 빠져 있으면 지금처럼 달 기준이에요.

## 2. '지금 좋아요' 기간
| 안 | 단풍 | 꽃 | 좋은 점 · 아쉬운 점 |
|---|---|---|---|
| **가(기획안, 추천)** | 절정 ±7일 | 개화일 ~ 만개 +7일 | 이해하기 쉬움. 꽃은 피기 시작할 때부터 알려 줌 |
| 나(짧게) | 절정 −5 ~ +5일 | 만개 −3 ~ +5일 | 가장 예쁠 때만. '지금'이 짧아 놓치기 쉬움 |
| 다(단계 나누기) | 첫 단풍 ~ 절정 +7일 | 개화 ~ 만개 +7일 | 예측에 '첫 단풍'이 있을 때만 가능 |

- **곧 좋아요:** 시작 14일 전부터 시작 전날까지
- **지났어요:** 끝난 다음 날부터

**가**로 시작하고 베타 의견으로 숫자만 조정해요. 숫자는 한 곳(`src/domain/seasons.ts`의 상수)에 둬요.

## 3. 높이 보정
- **단풍:** 흔히 '산 위에서 하루 약 40m씩 아래로 내려온다'고 해요. 예측의 '절정'은 산 전체 기준(대략 중턱)이에요.
  - **산 위 −7일 · 중턱 0 · 산 아래 +7일**을 제안해요.
  - 기획안(+0·+3·+7)은 산 위를 기준으로 잡은 셈이에요. 예측 기준이 '산 전체'라면 산 위가 늦게 잡혀요.
- **봄꽃:** 높이 100m마다 기온이 약 0.6℃ 낮아지고, 봄꽃은 1℃에 2~3일쯤 늦어진다고 해요. 그래서 100m당 1.5~2일이에요. 예측은 대개 낮은 곳(도시) 기준이에요.
  - **산 아래 0 · 중턱 +7일 · 산 위 +14일**을 제안해요.
  - 예: 비슬산·황매산 철쭉, 정상 근처 진달래
- 숫자는 모두 베타 뒤 조정 대상이에요. 근거 숫자(40m/일, 0.6℃/100m, 1℃당 2~3일)는 확인 필요예요.

## 4. 작년 기준
- **작년 실제 관측:** 기상청 계절관측(단풍 첫날·절정, 개화·만개)을 기상자료개방포털에서 받을 수 있어요(**확인 필요**: 지점 목록, 파일·API 여부, 키). 나중에도 받을 수 있어서 서둘러 남길 필요는 없을 가능성이 커요.
- **작년 예측(산림청 단풍 예측 지도 등):** 보도자료·그림이라 나중에 찾기 어려울 수 있어요.
  - **이번 시즌이 끝나기 전에 2026 가을 숫자를 `content/seasons/2026.json`에 남겨 두기를 추천해요.** 콘텐츠 세션이 보도자료의 산별 날짜와 출처 한 줄만 옮기면 돼요.
  - 그러면 처음 해(2027 봄·가을)에 '작년 예측'을 쓸 수 있어요.

## 5. 자동 갱신
| 자료 | 가져올 길(확인 필요) | 방법 |
|---|---|---|
| 기상청 계절관측(실제) | 기상자료개방포털 / 공공데이터포털 API(키 필요 가능) | GitHub 자동 작업이 시즌 중 주 1회 받아 데이터 PR |
| 산림청·국립수목원 단풍·봄꽃 예측 | 보도자료(그림·표). API 없을 가능성 큼 | 자동 작업이 '새 보도자료 확인' 이슈를 엶 → 콘텐츠가 숫자 입력 PR |
| 민간 예보(웨더아이 등) | 유료·저작권 | 쓰지 않음 |

- 기획안대로 **앱은 기관 서버에 묻지 않아요.** 순서는 이래요.
  1. 자동 작업이 정해진 날 가져오기
  2. 데이터 PR
  3. 콘텐츠 확인
  4. 프프 합치기
- **시즌 중 예측이 고쳐지면** 같은 작업이 다음 주에 다시 돌아 바뀐 날짜만 PR로 올려요(`updatedAt`·`source`가 남음).
- 보도자료만 있는 기관은 완전 자동이 어려워요. **'자동 알림 + 사람 한 번 입력'**이 현실적인 목표예요.
- 키가 필요하면 GitHub Secrets에만 두고 코드·문서에 적지 않아요(CLAUDE.md 절대 규칙 4와 같은 방식).

## 6. 영향 범위
지금은 '달'로 판단하던 곳이 '날짜'로 바뀌어요.
| 곳 | 지금 | 바뀐 뒤 |
|---|---|---|
| '지금 좋아요' 배지(D12, `seasonNow`) | 오늘 달이 추천 시기 안 | 오늘 날짜가 장면의 날짜 범위 안 |
| 풍경 찾기 순서(D61, `typeGroups`) | 그달에 좋은 장면 수·달 범위 길이 | 같은 계산, 날짜 범위가 그달과 겹치면 '그달에 좋은 장면'. 길이·끝나는 날도 날짜로 |
| 첫 화면 카드 순서(D62, `orderPeak`) | 추천 시기 개월 수 | 날짜 범위 일수 |
| 앱 안 알림 카드 | 달 기준 | '곧 좋아요'(14일 전) 기준 |
| 백로그 #10(반달) | — | 날짜 범위가 생기면 저절로 해결 |
| 시험 | 달 기준 | 날짜를 고정한 시험 추가. **시기 파일이 없을 때 지금과 똑같이 동작**하는지가 핵심 |

## 7. 난이도 · 작업 순서 · 추천
**난이도: 중간.** 앱 계산보다 자료 쪽(보도자료 입력)이 손이 많이 가요. PR 5개쯤이에요.
1. **지금(콘텐츠):** 2026 가을 단풍 예측·관측 숫자를 `content/seasons/2026.json`에 남기기
2. 시기 파일 모양 + 빌드 때 계산 + 시험(화면 변화 없음)
3. 배지·'곧'·'지났어요'를 날짜 기준으로
4. 풍경 찾기·첫 화면·알림 카드
5. 자동 작업(기상청 관측 PR + 보도자료 확인 이슈)
6. 화면 문구는 그다음에 디자인과

**추천 일정:** 1번만 이번 가을 안에 하고, 2~5번은 12~1월에 해서 2월 봄꽃 예측 전에 돌게 해요.
